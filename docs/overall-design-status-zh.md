# QQ 智能体：项目架构与开发进度

更新日期：2026-10-11

这是一个运行在本地的 QQ 智能体项目。它使用 NapCatQQ 接入个人 QQ 账号，通过
OneBot v11 收发消息，并在上层连接 OpenClaw、Ollama、本地数据存储和运维服务。

项目没有修改 NapCatQQ 或 OneBot 的源码。NapCatQQ 负责 QQ 登录和协议适配，OneBot
负责统一消息事件与发送动作，本项目负责智能体逻辑、安全策略、模型调用、可靠投递、
记忆、群聊风格和故障恢复。

## 项目能做什么

- 将普通 QQ 私聊转交给 OpenClaw 智能体，并通过白名单限制可用账号；
- 为指定群聊绑定独立的 Ollama 模型与说话风格；
- 支持 `@机器人`、回复机器人以及模型判断后的主动插话；
- 从获得授权的社区内容中提取语言风格，定时更新风格画像；
- 提供长期记忆、待办事项、提醒、摘要和人工确认；
- 在模型或 QQ 临时不可用时保存待发送消息，恢复后自动重试；
- 通过本地管理面板、加密备份和 watchdog 维护运行状态；
- 提供 KanagawaWave v2 数据集处理与 QLoRA 训练配方。

本项目适合希望在自己的电脑上运行 QQ 智能体、能够自行部署 NapCatQQ/Ollama，并愿意
管理模型、授权来源和安全配置的用户。它不是托管机器人平台，也不提供绕过 QQ、Reddit
或贴吧平台规则的能力。

## 系统架构

```text
QQ 私聊 / QQ 群聊
        |
        v
NapCatQQ：登录 QQ、维持会话、适配 QQ 协议
        |
        v
OneBot v11 WebSocket：标准化消息事件与发送动作
        |
        v
QQ Agent Bridge
    +-- 白名单、限流、去重和触发判断
    +-- 私聊 ----------------------> OpenClaw Agent
    +-- 授权群聊 ------------------> Ollama / KanagawaWave 模型
    +-- 本地命令 ------------------> 记忆、待办、提醒和审批
    +-- 可选媒体与长任务 ----------> 独立媒体服务
        |
        v
SQLite + 可靠发件箱 -> OneBot v11 -> NapCatQQ -> QQ

辅助服务：
    Style Learner  -> 授权来源 -> 抽象风格画像 -> 按群绑定
    Dashboard      -> 本地管理、审批、备份和运行状态
    Watchdog       -> 健康检查与受限自动恢复
    Offline Trainer-> 审核数据集 -> QLoRA -> 合并模型 -> Ollama
```

各部分职责如下：

| 组件 | 作用 |
| --- | --- |
| NapCatQQ | 登录个人 QQ 账号并提供 QQ 协议能力，是需要单独安装的外部依赖。 |
| OneBot v11 | 在 NapCatQQ 和本项目之间提供统一的事件及动作格式。 |
| Bridge | 处理消息、权限、路由、模型调用、重试和最终回复。 |
| OpenClaw | 主要承担白名单私聊中的通用智能体能力。 |
| Ollama | 在本机运行群聊风格模型，包括 KanagawaWave 模型。 |
| SQLite | 保存消息状态、记忆、待办、审批、任务和审计记录。 |
| Dashboard | 提供仅限本机使用的管理与状态页面。 |
| Watchdog | 检查关键服务，并在设定的次数和冷却限制内尝试恢复。 |

- **可选**：代码已经提供，但默认关闭，需要额外服务、账号授权或人工配置；
- **实验中**：已经具备基础链路，暂时不应接管主要回复流程；
- **计划中**：当前仓库还没有完整可交付实现。

### 实验中

- 智能路由目前可以在后台进行风险分级、记录判断和统计效果，但不会接管正式回复；
- 编排层已经提供规划、执行、验收、预算和追踪接口，正式路径仍以单个主 Agent 为主；
- 训练后的 KanagawaWave 模型由外部 CUDA 训练机生成并手动导入 Ollama，公开仓库不包含
  模型权重。

### 计划中

- 日历、邮件、项目管理等外部业务连接器；
- 管家、记忆、调度、编码等专职 Agent 的协作与权限隔离；
- 按能力选择模型、全局 Token/费用预算和多模型交叉审核；
- 复杂任务的有向任务图、Worker 池和失败回收；
- Linux、Windows 与 macOS 一致的安装器、服务管理和密钥存储方案；
- 面向其他模型家族的通用训练流程。

这些项目是发展方向，不代表已经能够使用。仓库中的二次确认机制只能保护已经实现的操作，
不会让尚未开发的连接器或系统权限自动变为可用。

## KanagawaWave 训练范围

仓库内现有训练包位于 `training/kanagawawave_v2/`，它复现项目实际使用过的方案：

- 基础模型：`Qwen/Qwen3-4B-Instruct-2507`；
- 对话模板：`qwen3_nothink`；
- 方法：4-bit NF4 QLoRA；
- 提供 RTX 4060 8GB 和更低显存两套训练配置；
- 提供 adapter 合并、Safetensors/GGUF 和 Ollama 导入说明。

这是一套固定且可复现的 KanagawaWave v2 配方，不是所有 Ollama 模型通用的训练器。更换
模型家族或参数规模时，需要重新选择对话模板、LoRA 目标层、显存参数和转换工具，并重新
进行风格与安全验收。

公开仓库不包含原始社区归档、私人数据、训练输出、adapter、GGUF 或 Safetensors 权重。

## 安全与隐私原则

- QQ 消息、网页、Reddit、贴吧、附件和引用内容都按不可信输入处理；
- 私聊和群聊分别执行白名单、触发条件、长度、类型和频率限制；
- 只处理已获得授权的风格来源，并支持撤销授权后停用或重建画像；
- 风格学习提取表达特征，不把来源正文作为长期知识注入群聊；
- OAuth bearer、API Key、备份主密钥和本机配置不得进入仓库或回复内容；
- 模型不能绕过本地命令链、审批、媒体预算或工具限制；
- 数据集、数据库、日志、模型权重和 `.env` 文件不得提交到公开仓库。

部署者仍需遵守 QQ、Reddit、贴吧、模型及其他外部服务的规则，并为自己启用的数据来源、
模型输出和账号行为负责。

## 部署前需要准备

最小部署通常需要：

1. 一套可正常登录的 NapCatQQ 环境；
2. 配置正确的 OneBot v11 WebSocket；
3. Python 运行环境与本项目配置文件；
4. 用于私聊的 OpenClaw，或选择其他受支持的 Agent 适配器；
5. 用于群聊的 Ollama 和已经导入的模型；
6. 明确的 QQ 私聊白名单、允许群和触发策略；
7. 在真实 QQ 环境中完成消息、重试、重启和回滚测试。

可选模块应逐项启用。建议先稳定私聊、群聊、可靠发件箱和 watchdog，再开启主动插话、
社区风格学习、媒体或实验性路由。

因此，本项目适合技术用户进行本地部署和二次开发，但还不是下载后无需配置即可使用的
