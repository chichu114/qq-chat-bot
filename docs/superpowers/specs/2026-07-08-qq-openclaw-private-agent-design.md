# QQ 个人账号 OpenClaw 智能体设计方案

## 目标

构建一个本地最小可用版本，让使用者可以通过普通个人 QQ 号与智能体私聊。QQ 账号只作为消息载体，OpenClaw 负责智能体的行为、记忆和工具编排。

第一版只支持受信任 QQ 用户的私聊文本消息。不支持群聊、图片理解、语音、文件传输、支付、批量发消息，也不开放不受限制的本地命令执行能力。

## 推荐方案

使用 NapCatQQ 作为个人 QQ 账号适配器，通过 OneBot v11 WebSocket 暴露消息事件，再运行一个小型桥接服务，把 OneBot 和 OpenClaw 连接起来。

```text
使用者 QQ 账号
  -> 发送私聊消息
由 NapCatQQ 登录的机器人 QQ 账号
  -> OneBot v11 WebSocket 事件
桥接服务
  -> OpenClaw 智能体请求
OpenClaw 智能体
  -> 桥接服务
  -> OneBot send_private_msg
  -> QQ 私聊回复
```

这样可以把 QQ 协议层和智能体层分开。后续如果 NapCatQQ 或 QQ 协议行为发生变化，通常只需要调整适配器侧，而不需要重写智能体逻辑。

## 组件

### NapCatQQ

NapCatQQ 负责登录机器人 QQ 账号，并提供 OneBot v11 连接能力。它负责接收私聊消息和发送 QQ 回复。

需要配置：

- 机器人 QQ 账号的登录凭据和登录状态。
- 本地可访问的 OneBot WebSocket 地址。
- 开启私聊消息接收。
- 允许通过 `send_private_msg` 发送私聊消息。

### 桥接服务

桥接服务是一个本地常驻的小进程。它连接到 NapCatQQ 的 OneBot WebSocket 地址，过滤收到的事件，把通过校验的消息发送给 OpenClaw，再把 OpenClaw 生成的文本回复转发回 QQ。

职责：

- 连接 OneBot WebSocket，并在断开后自动重连。
- 只接受 `private` 类型的私聊消息事件。
- 检查发送者 QQ 是否在 `ALLOWED_QQ_USERS` 白名单中。
- 第一版忽略空消息和不支持的消息类型。
- 对每个用户做基础频率限制。
- 为日志添加请求 ID，方便追踪一条 QQ 消息在系统中的完整流转。
- 把 OneBot 事件转换成稳定的内部请求格式。
- 把 OpenClaw 响应转换成普通文本 QQ 回复。

桥接服务不应该内置智能体的人格提示词或业务逻辑。这些内容应该放在 OpenClaw 中维护。

### OpenClaw 智能体

OpenClaw 负责真正的智能体行为。桥接服务通过一个小的适配接口调用 OpenClaw，这样后续可以根据本地环境选择最合适的 OpenClaw 入口：HTTP 服务、命令行或 SDK。

第一版智能体配置应包含：

- 清晰的私人助手系统提示词。
- 以 QQ 用户 ID 为键的短期对话上下文。
- 安全的工具默认配置。
- 默认不启用破坏性工具。

### 配置

配置应放在环境变量中，或放在已被版本控制忽略的本地 `.env` 文件中。

初始配置项：

- `ONEBOT_WS_URL`：NapCatQQ 提供的 OneBot WebSocket 地址。
- `BOT_QQ`：由 NapCatQQ 登录的机器人 QQ 账号。
- `ALLOWED_QQ_USERS`：允许触发智能体的 QQ 号列表，使用英文逗号分隔。
- `OPENCLAW_ENDPOINT`：OpenClaw 服务地址，或等价的 OpenClaw 启动配置。
- `RATE_LIMIT_MESSAGES_PER_MINUTE`：每分钟消息频率限制，建议默认值保守一些，例如 10。
- `LOG_LEVEL`：日志等级，默认使用 `info`。

## 消息流程

1. 使用者向机器人 QQ 账号发送私聊文本消息。
2. NapCatQQ 产生一个 OneBot 私聊消息事件。
3. 桥接服务校验消息类型、发送者白名单和频率限制。
4. 桥接服务创建智能体请求，包含 `user_id`、`message_id`、`text` 和时间戳。
5. 桥接服务把请求发送给 OpenClaw。
6. OpenClaw 返回文本回复。
7. 桥接服务通过 OneBot `send_private_msg` 发送回复。
8. 桥接服务记录处理结果，但不保存敏感凭据。

## 错误处理

如果 OneBot 连接断开，桥接服务应使用退避策略自动重连，并记录连接状态变化。

如果 OpenClaw 不可用，桥接服务应发送简短的兜底回复，例如“智能体暂时不可用，请稍后再试。”QQ 消息中不应暴露堆栈信息或凭据。

如果发送者不在白名单中，桥接服务应静默忽略该消息。

如果回复过长，桥接服务可以带明确后缀地截断回复，或拆分成多条消息并加少量延迟发送。最小可用版本建议先采用截断方案，因为实现更简单，也更不容易触发刷屏风控。

如果收到不支持的消息，例如图片、语音或文件，桥接服务只对已加入白名单的用户回复一条简短提示，说明第一版只支持文本。

## 安全边界

普通个人 QQ 号方案依赖非官方 QQ 协议工具。QQ 行为变化时可能失效，也可能带来账号风险。最小可用版本应使用备用 QQ 号，不建议直接使用主力账号。

默认安全策略：

- 仅允许白名单访问。
- 仅支持私聊。
- 使用保守的频率限制。
- 不做群发或广播。
- 默认不开放本地 shell 执行工具。
- 不开放文件删除、支付等高风险工具。
- 日志避免输出完整凭据；只有在调试确实需要时才记录消息内容。

## 测试计划

单元级检查：

- 私聊消息事件会被接受。
- 群消息事件会被忽略。
- 非白名单发送者会被忽略。
- 空消息和不支持的消息类型有可预期的处理结果。
- 频率限制能拦截过多消息。
- OpenClaw 出错时会生成兜底回复。

手动集成检查：

- 启动 NapCatQQ，并确认 OneBot WebSocket 可连接。
- 启动 OpenClaw，并确认桥接服务可以调用它。
- 使用白名单 QQ 用户发送私聊消息，并确认能收到回复。
- 使用非白名单 QQ 用户发送私聊消息，并确认不会收到回复。
- 停止 OpenClaw 后发送消息，确认会触发兜底回复。
- 重启 NapCatQQ 后，确认桥接服务可以自动重连。

## 实现顺序

1. 创建桥接项目骨架和配置加载器。
2. 实现 OneBot WebSocket 连接和事件解析。
3. 添加白名单、私聊过滤和频率限制。
4. 添加临时的 echo OpenClaw 适配器，用于本地测试。
5. 确认本地 OpenClaw 入口后，把 echo 适配器替换为真实 OpenClaw 集成。
6. 添加日志，并围绕过滤逻辑和错误处理补充基础测试。
7. 编写本地启动流程文档。

## 已确认事项

- 第一版通道：仅私聊。
- QQ 载体：通过适配器接入普通个人 QQ 账号，不使用 QQ 开放平台 Bot API。
- 首选适配器：优先使用 NapCatQQ；如果后续需要，再考虑 Lagrange.OneBot 作为备选。
- 第一版回复类型：仅文本。
- 第一版访问策略：仅白名单。
