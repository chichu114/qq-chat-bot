# E3 长期记忆 2.0 设计

## 目标

在不删除 E1、E2、E2.5 已有能力的前提下，把 chichu 从“Markdown 备忘录”升级为可确认、可检索、可审计、可控成本的长期记忆系统。

## 不变边界

- QQ 私聊白名单、限流、单用户顺序、消息去重和 Outbox 不变。
- 现有 `记住：...`、`查看记忆`、`搜索记忆`、待办、提醒、风格指令继续可用。
- SQLite 仍是正式数据源，Markdown 仍是可读导出，不恢复为并发数据库。
- 主对话仍走 E2.5 的 `PlanningStrategy -> ExecutionEngine -> VerificationStrategy`。
- 记忆分析失败不能阻塞普通回复，也不能把内部错误发给 QQ 用户。

## 分层模型

1. **人格核心**：名字、身份、行为边界和基础语气，由精简后的 `AGENTS.md`、`SOUL.md` 管理。
2. **用户档案**：姓名、偏好、稳定习惯等已确认事实，存入 SQLite。
3. **动态风格**：`STYLE.md` 中的用户反馈继续保留，由上下文编译器去重和限长。
4. **长期记忆**：项目、约束、决定、经历等已确认事实，存入 SQLite；`MEMORY.md` 继续作为兼容导出。
5. **对话摘要**：按用户、按连续轮次生成，不等同于长期事实，不需要全部注入。

## 数据与状态

SQLite schema 从 v2 升级到 v3，新增：

- `conversation_turns`：保存用户与 chichu 的对话轮次。
- `conversation_summaries`：保存摘要、关键词、向量和覆盖的轮次范围。
- `memory_facts`：保存候选、已确认、已拒绝的事实及来源、置信度、关键词和向量。
- `memory_analysis_runs`：保存轻量分析任务的成功/失败状态，便于面板和 watchdog 观察。

迁移只使用 `CREATE TABLE IF NOT EXISTS` 和索引创建，不删除 v2 表或历史数据。

## 写入流程

1. 普通回复成功投递后，记录用户消息和助手回复。
2. 当未摘要轮次达到阈值时，在后台触发一次分析，不占用 QQ 普通对话锁。
3. 配置了轻量模型时，用独立 session 调用轻量模型完成“摘要 + 重要事实分类”；未配置或调用失败时使用本地保守摘要，不自动编造事实。
4. 自动提取的重要事实只进入 `pending` 状态。
5. 用户通过 `确认记忆 <id>` 或面板确认后，事实才变成 `confirmed` 并可注入主模型；`拒绝记忆 <id>` 永久排除该候选。
6. 用户明确发送 `记住：...` 时，沿用原指令并视为主动确认，直接写入已确认层。

## 检索与上下文

- 先做中文/英文关键词匹配，再用确定性的特征哈希向量计算余弦相似度。
- 对关键词得分、向量得分、时间和层级加权，只选当前问题相关的已确认事实和摘要。
- 上下文采用独立 `AgentRequest.context` 字段，不改写用户原始文本，不影响本地命令和安全确认。
- 对人格、用户档案、动态风格、长期记忆和摘要分别设数量与字符上限，最后统一执行总预算裁剪。
- 候选、拒绝、低相关和未确认内容永远不注入主模型。

## 人格压缩

- 用编译器按规范化文本去重 `AGENTS.md`、`SOUL.md`、`STYLE.md` 中的重复规则。
- 部署时先备份，再把 `AGENTS.md` 和 `SOUL.md` 收敛为 E3 的短版核心；`STYLE.md` 保留动态反馈。
- 运行时只注入当前用户相关的短上下文，避免每轮把全部记忆塞给模型。

## 模型分工

- `OPENCLAW_MODEL`：主对话模型，继续处理复杂任务。
- `MEMORY_LIGHT_MODEL`：只处理摘要和事实分类，推荐使用当前 OpenClaw 已可用的 `openai/gpt-5.4-nano`；独立 session 前缀自动与 `OPENCLAW_AGENT_ID` 对齐。
- 轻量分析采用独立 session prefix，失败时自动退回本地摘要，不调用主模型补偿，避免成本失控。

## 风格防漂移

- 固定身份锚点：`chichu / 本地 QQ 私聊管家 / 中文 / 先办事后毒舌`。
- 禁止项：客服模板、油腻暧昧、人格攻击、反复自我介绍、把内部报错原样外发。
- 回归测试同时检查人格编译结果、身份回答和上下文预算，防止“越学越油”或规则无限增长。

## 可观测与管理

- QQ 新增：`待确认记忆`、`确认记忆 <id>`、`拒绝记忆 <id>`、`记忆状态`。
- 面板展示分层计数、待确认事实、最近摘要、轻量模型和分析状态，并支持确认/拒绝。
- runtime metrics 记录最近分析成功、失败和待摘要轮次数。

## 验收

- schema v3 迁移保留 v2 数据。
- 未确认事实不会进入上下文；确认后能被关键词与向量混合检索命中。
- 摘要任务不阻塞普通回复，失败后普通聊天仍正常。
- 旧命令、提醒、投递、审批和面板能力回归通过。
- 人格文件压缩后保留 chichu 核心身份与安全边界。
